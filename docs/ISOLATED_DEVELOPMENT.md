# 本地隔离开发与验收

使用 Node.js 22+，先在仓库根目录运行 `npm install`。启动：

```bash
npm run dev:isolated
```

默认页面为 `http://127.0.0.1:3100`，后端为 `http://127.0.0.1:4100`。端口被占用会停止，不会切换到另一个环境。可通过 `--frontend-port 3101 --server-port 4101` 指定其他端口。

每次新建系统临时目录内的私有环境，终端打印完整目录及恢复命令。数据库 `x-computer.db`、账号、任务、记忆、通知、文件及私有配置属于此环境。不会复制原账号、任务或数据。重启并保留进度时，使用打印的命令：

```bash
npm run dev:isolated -- --resume /完整路径/x-computer-isolated-实际编号
```

只有带正确标识、私有权限、真实路径及 SQLite 配置的环境可以恢复。不会覆盖已有配置，不会自动删除验收数据。临时目录可能被操作系统清理；需要长期保留时应先停止服务，再把整个目录复制到用户自己的私有持久目录，权限保持为目录 `700`、配置与标识 `600`，从新路径恢复。不要只复制主数据库文件：运行中的 SQLite 可能还有 WAL 数据。

## 真实模型

未指定模型时没有平台模型密钥；可先初始化，编辑打印出的 `config.private.json` 中的 `llm_config`，再恢复：

```bash
npm run dev:isolated -- --init-only
```

也可显式指定一个已有配置文件，只把它的 `llm_config` 复制进新环境：

```bash
npm run dev:isolated -- --model-config /完整路径/模型配置.json
```

源文件只读。不会复制数据库、SMTP、OAuth 或 MCP 设置。模型配置中的 `{env:变量名}` 从启动该命令的终端解析后写入权限 `600` 的私有副本；缺失变量则拒绝启动。不要提交、展示或公开此配置。真实模型请求仍会产生供应商费用。

## 数据保护边界

- 子进程使用筛选后的环境，不继承原 MySQL、支付、渠道凭据或 Node 预加载参数；跳过项目的 `server/.env`。
- 前后端仅监听本机。独立前端将 API 和 WebSocket 都转发至指定后端，不会默认连到原 `4000`。
- 独立端口同时登记精确的本机前端来源，避免 WebSocket 被默认开发端口白名单误拒绝。不会放行任意本机端口；生产模式不使用这条开发来源豁免。
- 登录 Cookie 按隔离目录区分，避免同一主机不同端口覆盖原环境的登录态；迁移目录后需要重新登录。
- 恢复前拒绝运行数据中的符号链接及与外部共享的文件硬链接，包括用户目录和 SQLite WAL/SHM；完整位于环境内的材料硬链接可以恢复。超过十万条目录项时停止，需单独审核迁移。
- 启动前校验目录和配置，服务入口再次校验；MySQL 配置、未知目录或集成配置会被拒绝，不回退原配置。
- 默认关闭容器，只启用轻量档及生产力、自动化模块。这是本机验收环境，**不是恶意代码安全沙箱**，不要执行不可信代码，也不要用它对外部署。完整 Docker 浏览器能力需另用已配置的容器验收环境。
- Ctrl+C 停止前后端进程，记录和文件保留。开发 watch 自动重载不等于任务完成；仍应核对实际成果及验收状态。

快速保护检查：`npm run test:isolated`。公开部署、完整备份恢复、生产升级及多机运行仍需单独验收。
