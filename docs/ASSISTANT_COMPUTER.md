# 助手电脑：浏览器与控制权交接

浏览器应用默认进入“助手电脑”，原 iframe 入口保留在“网页预览”。两者并不等价。

## 已实现范围

复用 UserContainerManager，为用户创建独立的浏览器容器，名称前缀为 x-computer-browser，数据位于工作区根目录下 browser-computers/users/{userId}/workspace。它不与 Shell 容器共用进程或挂载目录，不向宿主发布浏览器端口。服务端通过 Docker exec 传输受限 JSON 操作，HTTP 路由以 Cookie 身份确定用户和人工操作身份。

用户明确点“打开助手电脑”才创建资源；读取状态不创建或启动容器。首次启动和容器重启均由用户掌控。用户可点画面、输入文字、发送受限按键或滚动。画面以截图定时刷新，并非视频流。输入不自动清空，失败后不自动重试操作。

“我来操作”和“交还助手”与浏览器动作使用同一串行队列。接管返回成功时，先前的浏览器动作已结束；助手无法继续使用 browser.* 动作。交还使旧快照失效；助手必须重新观察。每次助手操作均需携带观察得到的快照标识，并操作对应元素引用。

browser.observe 与 browser.act 已注册到现有工具执行器，并允许基础账号发现。人工控制期间，调用等待用户交还而不重复请求模型；停止信号可以中止等待。现有通知记录提示用户交还，等待结束后标记已处理。文件提供有显式参数绑定确认；通用高风险动作的统一审批仍待实现。

## 启用

默认关闭。不要为本地验收使用原 MySQL 配置。构建镜像：

```sh
docker build -f docker/browser.Dockerfile -t x-computer-browser:local .
```

在独立的配置副本中设置 container.browserEnabled=true、container.imageName 为上述镜像，建议 memoryLimit="1g"、pidsLimit=256、networkMode="none"。浏览器功能可独立于 Shell 容器启用。浏览器数据不按空闲时间自动删除，保留登录资料。

本轮实际验收使用官方 Playwright 镜像及同版本官方 npm 包。因容器内 npm 下载阻塞，验收镜像通过临时构建目录离线解包该包生成；未关闭 TLS 校验。仓库额外保留了基于已有 Alpine 沙箱的开发构建方案，该方案尚未通过本轮验收，不作为推荐镜像。

外部网站默认无授权来源。管理员可设置 container.browserNetworkMode="bridge" 与 browserAllowedOrigins（精确 origin，包括协议和端口），浏览器网络独立于 Shell；不支持浏览器 host 网络。没有单独配置时兼容既有 bridge 设置，其他情况保持 none。

所有浏览器 HTTP/HTTPS 连接经过容器内回环代理。每次连接检查来源、解析结果，拒绝内网、环回、保留地址与 IPv6，然后直接连接已校验的数字 IPv4，避免校验后再按域名解析。HTTPS 保留浏览器的真实站点证书校验，没有关闭 TLS 校验或设置忽略证书错误。页面请求另有来源拦截，WebSocket 与 Service Worker 当前禁用。此范围仅覆盖本浏览器通道，不能代替整个项目的出口防火墙或完整安全验收。

默认使用系统 DNS。fake-IP 网络可由管理员显式设置 browserDnsMode="cloudflare"，通过固定地址的 HTTPS DNS 查询获得真实地址，再执行相同的地址检查；不会放行 198.18/15 等保留地址，也不修改宿主 DNS/VPN。该选项把已授权网站的域名发送至 Cloudflare，协议依据见 [Cloudflare 官方说明](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。仅对只读解析请求设置备用解析地址；不会自动重试网页点击、提交等动作。缓存仅保留已校验的公网数字地址。

网络发生变化或页面超时时，保留用户填写的网址并提示先查看画面再决定是否重试。页面错误不会被当作成功导航；HTTP 错误状态也会明确报告。

## 当前边界

当前是浏览器电脑，不是完整 Linux 桌面。仅单标签页；不提供任意脚本执行；文件提供需通过下述单次确认通道。浏览器下载与 ChatRun 成果交付已接通，外部网站下载仍待联网验收。容器控制权保护覆盖本浏览器通道，不代替整个项目已有的宿主 Shell、ServerManager 等安全审计。高风险网页操作的逐项参数审批仍需加强，不能直接开放付款、发布或删除等真实业务验收。

接管交接不是完整的任务调度恢复机制；ChatRun 仍保留原有单进程执行权限制，电脑恢复后不会自动重放结果未知的操作。记忆管理未改动。

## 本轮实际验收结果

2026-10-30，独立 SQLite 验收环境中已用真实模型完成：人工输入 → 模型等待交还并产生待处理通知 → 用户交还 → 模型读取练习页、填写文字、点击展示、重新观察 → ChatRun 完成 → 用户确认验收。实际页面显示“助手接着做啦”。工具记录仅有能力发现/加载和 browser.observe / browser.act；一次过期快照操作被拒绝，模型重新观察后完成。

## 网页下载与成果交付

已完成的下载保存在浏览器独立目录 `.x-browser/exports`，不扫描登录资料或用户指定的任意路径。单文件限制10MB、导出目录累计限制20MB，同时下载限制为两个。下载完成后记录大小与 SHA-256；失败或仍在下载的内容不列为完成。内存临时下载还受容器 `/tmp` 的空间限制。

browser.downloads 列出当前用户已完成的下载；browser.present_download 使用不透明下载 ID，重新校验源文件并复制至用户工作区“下载”目录。本次交付复用 ChatRun 的成果提取、待验收、退回和委托同步。浏览器面板的“保存并打开”只保存并打开文件，不自动创建一项已完成交办，也不替用户确认验收。

交付不覆盖原稿或用户改过的成果。临时完整写入后以硬链接原子发布；重试复用同一路径，目标已改动则明确拒绝覆盖。源文件与目标目录的符号链接会被拒绝，传输对象只来自当前用户的完成清单。

## 向网页提供文件的确认通道

模型通过 browser.request_upload 提交用户工作区文件相对路径、当前 snapshot 与 type=file 的目标索引。服务端检查普通文件、工作区边界与大小，计算内容指纹；不会把文件内容放进申请回执或通知。用户从“需要你处理”的“去处理”可返回已有助手电脑窗口，通知本身不能批准上传。卡片展示文件路径、大小、网页和选择框；确认意味着网页脚本可以读取文件，可能立即发送给网站服务端。

确认时重新校验文件指纹、页面 URL、快照、元素身份及选择框属性。文件、页面或选择框变化时拒绝执行。审批绑定请求 ID，只能由经过认证的用户作出；模型通用浏览器动作限制为导航、点击、输入、按键和滚动，不能调用确认 RPC 或读取人工控制中的状态/画面。专用文件通道不接受模型伪造的批准状态。

请求写入容器私有控制记录，待确认期间不重复调用模型。用户拒绝或正常停止后不提供文件；请求超时和浏览器重启使待确认授权失效。执行前先持久标记 consumed，结果丢失后不会自动重放；浏览器重启将未决执行标为 unknown。只对完成的选择操作返回“已提供给网页”，不把它当作网站处理成功。模型必须重新观察并核实网页回执。

文件大小上限5MB。确认后暂存独立副本，使用原生 FilePayload 提供给明确的选择框，之后清理暂存副本；原文件不删除、不覆盖。文件链接与命名管道受检查，Linux 在读取前验证已打开文件描述符仍位于工作区。宿主 Shell、生成应用隔离等其他通道仍须完成整体安全验收，不能把此功能视为整个系统的安全资格证明。
