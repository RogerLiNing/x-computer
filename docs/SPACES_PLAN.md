# 共享空间方案

> 状态：已确认，按步骤实施中。需求来自 2026-11-07 的访谈。
> 第一个真实用例：Roger 和老婆的家庭空间，放宝宝资料、日常提问。设计本身是通用的，不为某个场景做专用功能。

## 1. 需求（访谈结论）

- **通用小组**：任何几个人都能建空间（家庭、朋友、项目组），一个人可以同时在多个空间里。
- **各自的助手，共用空间**：每人有自己的助手，私人对话和私人记忆互不可见；空间是大家共用的地方。
- **空间里共享**：
  - 文件资料
  - 助手记住的事
  - 日程和提醒
  - 任务的进度和结果。其他成员看不到原话。
- **归属判断**：一句话是私事还是某个空间的事，由助手判断，判断后告诉用户放到了哪里；拿不准就问。
- **通知**：只在重要变化时通知其他成员，平时不打扰。
- **入口**：先用现有的 QQ 渠道。每个人配置自己的 QQ 机器人和自己的模型密钥。H5、小程序、App 都只是渠道，以后再做，不影响这里的设计。
- **最大痛点**：配置太多、经常出错或卡住、不知道它在干什么、功能太杂。所以空间功能必须做到简单、可靠、过程可见，不能再增加新的复杂度。

## 2. 现状（代码调研）

| 能力 | 现状 | 对空间的影响 |
|---|---|---|
| 用户隔离 | 沙箱目录 `users/<id>/workspace`，有测试专门保证 A 看不到 B 的文件 | 空间数据要放在单独的目录，成员身份校验后才能访问 |
| 记忆 | 以文件形式存在用户沙箱的 `memory/` 下 | 空间有自己的 `memory/`，加载方式相同 |
| 向量索引 | 已按 workspaceId 分区 | 空间用 `space:<id>` 作为分区 |
| QQ | 按用户连接自己的官方机器人，有私聊白名单，重启自动重连；**只处理文字，图片和文件会被丢弃** | 存资料需要补上附件接收 |
| 渠道消息 | 排队成该用户的 ChatRun，有进度、停止、恢复、验收 | 空间任务直接复用，不建第二套执行器 |
| 调度 | 按用户运行，已有渠道作用域 | 空间日程到点时，展开成每个成员各自的提醒 |
| 自配模型 | 只有专业版和管理员能配置个人模型（`userConfigAccess.ts`） | **和"用自己的密钥"冲突**，需要放开，或者改成默认允许 |

## 3. 设计

### 3.1 数据模型
- `spaces(id, name, created_by, created_at)`
- `space_members(space_id, user_id, role, joined_at)`：role 只有 `owner` / `member` 两种
- `space_events(id, space_id, actor_user_id, kind, summary, ref, importance, created_at)`：空间动态，用于"看进度和结果"和"重要变化才通知"，只存摘要和引用，不存对话原文
- 存储目录：`spaces/<spaceId>/workspace/`，下面有 `files/`、`memory/`
- 加入：owner 生成一次性邀请码，有效期较短，对方在自己的助手里发邀请码即可加入。可以退出空间；owner 可以移除成员

### 3.2 助手如何使用空间
- 每次对话时，助手的上下文里会有："你属于哪些空间（名称、成员）"，以及每个空间的记忆摘要。
- 工具层统一使用 `space` 参数，不新造一套平行的工具：
  - 文件工具：路径带空间前缀，例如 `空间:家庭/资料/...`。先校验成员身份，再映射到空间目录。仍然不允许符号链接。
  - 记忆工具：`remember(content, space?)`，`recall(query)` 同时查个人和所属空间，结果标明来源。
  - 日程工具：创建日程时可以指定空间。
- 容器模式：成员容器额外挂载 `/workspace/空间/<名称>`。成员关系变化时，重建容器或刷新挂载。

### 3.3 归属判断
- 由助手决定一条信息放在个人还是哪个空间；**写入后必须在回复里说明**，比如"已记到「家庭」空间"。
- 拿不准，或者用户在多个空间里都可能相关时，用现有的 `x.ask_user` 提供选项让用户选。
- 用户说"放错了，移到我自己这"，助手要能移回去。
- 只在写入空间时判断归属，读取时不限制：查询会同时查个人和所属空间。

### 3.4 可见性和通知
- 其他成员能看到的：空间动态（谁、做了什么、结果在哪），以及空间里的文件、记忆、日程本身。
- 其他成员看不到的：成员和自己助手的对话原文、私人记忆、私人文件。
- 每条空间动态标一个 `importance`：
  - **重要**：通过对方自己的 QQ 机器人通知其他成员。包括新增或修改日程、修改关键记忆、明确要求"告诉她"的事项。
  - **普通**：存文件、普通笔记，只写进动态，不推送。
- 同一成员短时间内的多条通知合并成一条，避免刷屏。
- 通知只发给空间成员本人绑定的私聊，作为预先授权的出站类型。发给其他任何人仍走现有审批。

### 3.5 QQ 附件
- 接收图片和文件：下载后先放在发送者的个人收件箱，然后按 3.3 判断要不要放进空间。
- 图片自动 OCR，生成同名的文字版，用于检索和回答。

### 3.6 配置更简单
空间功能本身不新增任何配置项。另外配合做两件事：
- 放开个人模型配置限制，让用户能用自己的密钥。
- 用户的 QQ 机器人或模型密钥失效时，在能联系到用户的地方明确告知，不能悄悄不回消息。

## 4. 分步实施和验收

每一步用 Roger 和老婆的两个真实 QQ 账号实际验收，测试通过不算完成。

| 步骤 | 内容 | 验收 |
|---|---|---|
| 0 | 放开自配模型限制；确认两个 QQ 机器人在真实账号上能稳定收发 | 两人各自在 QQ 私聊问一句话，都能得到回复；关掉服务再启动，机器人自动恢复 |
| 1 | 空间表、邀请加入、退出；助手上下文里带上空间信息（代码已完成：`server/src/spaces/`、`x.space_*` 工具，待真实 QQ 验收） | Roger 建「家庭」空间，老婆用邀请码加入，两人分别问"我在哪些空间"，回答正确 |
| 2 | 空间文件和空间记忆；归属判断，写入后说明，拿不准就问 | Roger 说"预产期是 X 月 X 日"，助手回复已记到「家庭」；老婆问"预产期哪天"能答对并说明来源；Roger 的私事不会出现在空间里 |
| 3 | 空间动态和重要变化通知 | Roger 加一个产检日程，老婆的机器人收到一条通知；Roger 存一份普通文件，老婆不收到推送，但问起来能找到 |
| 4 | QQ 图片和文件接收、OCR | 拍一张检查单发给机器人，放进空间后，另一个人能问出单子上的内容 |
| 5 | 空间日程到点提醒所有成员 | 设一个 5 分钟后的提醒，两个机器人各收到一次，不重复 |

## 5. 这一阶段不做
- H5、小程序、App 等新渠道
- 新的桌面小应用
- 更细的角色和权限、空间之间的共享
- 修改私人记忆的现有策略

## 6. 已确认的默认值（2026-11-08）
1. "重要变化"先按 3.4 的定义执行，用起来再调整。
2. 平台管理员默认看不到空间内容，排查问题时需要用户授权。
3. 每个空间最多 20 人。
