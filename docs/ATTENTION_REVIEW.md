# 需要你处理与成果验收

普通助手与 X 主脑共用“需要你处理”入口，读取现有 ChatRun、逾期且未完成的委托，以及未读的异常/决策通知。使用来源编号作为稳定键，不创建重复通知；解决、确认或来源状态改变后，事项从汇总中消失。通知的“标为已处理”复用既有已读接口，不改变任务状态。

执行结束进入成果待验收，用户可查看正文、打开已校验成果、确认或填写意见退回。验收记录保存在原 ChatRun 中，不改变执行成功与失败的定义。验收请求携带执行版本，拒绝旧页面覆盖新决定。已确认成果不能再退回。

用户选择关联委托后，确认成果也完成该委托。两个写入之间发生故障时，保留明确的待同步状态，允许重试，不把未完成的同步隐藏。退回仅记录意见，明确点击“按意见重新交办”才创建独立的修改执行；新旧成果、执行及修改意见保留，重复点击不会重复创建同一修改。修改仍使用原 ChatRun 执行、停止及恢复机制。

新增接口：

- GET `/api/chat/runs/attention`：按当前用户读取需要处理的来源记录。
- POST `/api/chat/runs/:id/review`：提交 accepted 或 changes_requested、expectedUpdatedAt、可选 feedback 和 delegationId。
- POST `/api/chat/runs/:id/revise`：明确启动退回后的修改交办，继续受额度控制。

没有新建任务引擎或修改记忆管理。沿用现有单服务进程执行所有权边界。当前验证包含服务回归、已有 HTTP 生命周期、前端状态回归及两端构建；未完成真实模型与浏览器交互验收。
