# 持续型个人助理的产品方向

目标是让用户像给一个熟悉自己的助手发消息：交代目标后，助手持续推进；有结果带回作品，需要决定时明确询问。主入口保持简单，支持工作和日常任务。界面容易操作并不等于已完成儿童独立使用的安全资格验证。

## 产品研究依据

- [OpenAI dots 使用说明](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)：持续目标、活动记录、作品反馈，以及由用户控制的电脑和应用访问。
- [Meta Muse 官方介绍](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)：像发消息一样交办，关注用户的长期目标，控制连接服务的访问范围。
- [Claude Duet 官方产品页](https://claude.com/product/claude-duet)：主动提示需要关注的事项，在用户离开时继续工作，带回文档、表格等成果供检查。

这些是厂商公布的产品机制，不是对内部实现的验证，也不是本项目已经达到同等能力或安全水平的证明。

## 当前这一轮落地

统一助手工作台跨对话汇总三类真实记录：正在做、等我决定、我的作品。复用 ChatRun 的接单、执行、停止、恢复、验收和修改，不建立第二套执行器。既有通知和委托继续进入待决定来源。

工作台接口只返回必要的标题、状态、时间、成果和操作入口，不返回模型密钥、系统提示或完整执行上下文。用户点开一项后再读取完整记录。正常读取进度不会启动模型、开始新工作或自动批准成果。

所有正在进行的任务都保留在列表；已结束历史只取最近一段，并明确提示有更早记录。完成、暂停和待验收含义分开，文件只来自服务端已记录的交付物。前端轮询和手动刷新会拒绝失效请求的迟到响应。

新增 GET `/api/chat/runs/workbench`，仍通过服务端会话确定身份。工作台内可打开作品，也可进入既有检查、停止、恢复和验收界面。

## 后续实现顺序

1. 将真实执行环境做成可检查、可接管的电脑与浏览器。先完成隔离和权限验证，再开放更多自动动作。
2. 从用户明确订阅的只读事项开始主动服务，显示来源、更新时间及取消入口；状态未变时保持安静。没有真实连接的邮箱和日历不能宣称已检查。
3. 对发送、发布、删除等副作用补足绑定实际参数的服务端授权，再接真实连接器。
4. 可审阅、可撤销的记忆管理后续再补，本轮不修改记忆策略。

持续在线还依赖部署和运行保障，不能把浏览器关掉后仍能执行，等同于已经具备全天候可用的云端服务。本轮仍保留现有单服务进程执行权限制，其他安全审计问题也需要继续关闭。
