# X-Computer 核心与插件架构

## 产品目标

X-Computer 的核心产品不是一套预装全部能力的 Web 办公软件，而是一台 AI 可以理解、操作和扩展的轻量虚拟电脑。

架构必须同时满足：

- 核心系统在低配置设备上快速启动。
- 默认不启动无关后台任务、消息连接和调度器。
- 应用只在用户打开时加载。
- 扩展能力具备明确权限、资源预算和生命周期。
- 禁用插件不删除用户数据，重新启用后可以继续使用。

## 系统分层

```text
┌────────────────────────────────────────────┐
│                 用户与 AI                   │
├────────────────────────────────────────────┤
│ 核心桌面：窗口 / 任务栏 / 搜索 / 通知 / 设置 │
├────────────────────────────────────────────┤
│ AI 核心：对话 / 上下文 / 工具入口 / 审计      │
├────────────────────────────────────────────┤
│ 系统核心：文件 / 终端 / 浏览器 / 身份 / 健康   │
├────────────────────────────────────────────┤
│ 插件运行时：清单 / 权限 / 启停 / 资源预算      │
├────────────────────────────────────────────┤
│ 可拔插能力：办公 / 渠道 / 自动化 / MCP / 商业化 │
└────────────────────────────────────────────┘
```

## 核心应用

核心应用始终可见、不可停用：

- AI 助手
- X 主脑
- 文件管理器
- 终端
- 浏览器
- 文本编辑器
- 系统设置
- 插件中心
- 系统监控

核心只承担“让 AI 可以使用这台电脑”的最小闭环。代码编辑、Office、邮件、日历、生产力工具、通信渠道和运营后台都属于插件。

## 插件契约

共享契约位于 `shared/src/index.ts`，插件至少声明：

```ts
interface PluginManifest {
  id: string
  name: string
  version: string
  permissions: string[]
  startupPolicy: 'eager' | 'on-demand' | 'manual'
  resourceBudget?: {
    memoryMb?: number
    cpuPercent?: number
    backgroundTasks?: number
  }
  frontend?: {
    appId?: string
    entry?: string
  }
  backend?: {
    routes?: string[]
    tools?: string[]
  }
}
```

权限必须按最小授权原则声明。文件、网络、Shell、LLM、浏览器控制、调度和消息发送相互独立。

## 前端加载

前端应用由 `appRegistry.ts` 提供清单，由 `appLoaders.ts` 提供动态模块入口。

启动过程只加载桌面外壳。应用第一次打开时，`React.lazy` 才请求对应 chunk。插件中心负责切换内置插件状态，桌面和全局搜索只展示已启用应用。

第三方插件后续应通过签名包安装，并将前端入口放入独立 iframe 或受控模块沙箱，避免获得宿主页面的任意执行权限。

## 后端运行档位

后端由 `PluginRegistry` 控制可选服务：

| 档位 | 用途 | 默认行为 |
| --- | --- | --- |
| `lightweight` | 低配置、本地 AI 电脑 | 启动核心服务与无后台任务的账户套餐查询 |
| `balanced` | 日常个人使用 | 启用自主、自动化、生产力、心跳、账户套餐和文档索引 |
| `full` | 服务器或团队部署 | 启用全部内置插件 |

环境变量：

```bash
X_COMPUTER_PROFILE=lightweight
X_COMPUTER_PLUGINS=mcp,messaging
X_COMPUTER_DISABLED_PLUGINS=heartbeat
```

显式启用和停用列表覆盖档位默认值。运行状态可通过 `GET /api/runtime/plugins` 查询。

## 性能规则

- 应用组件禁止在桌面入口静态导入。
- 后台插件未启用时不得创建定时器、轮询或外部连接。
- 工具默认使用 `on_demand` 模式，只向模型暴露发现与加载入口。

## 持续型 AI 内核

`LivingAIKernel` 是 X 的持续运行核心，不等同于一次性 Agent：

- 持久保存身份连续性、自我模型、内在驱动力、长期目标、反思和行动结果。
- 按“观察 → 反思 → 行动 → 休眠”循环运行，并在用户互动后提前唤醒。
- 支持观察、主动、自主三个等级；自主等级只允许在既有授权内执行低风险、可逆行动。
- 删除、覆盖、支付、发布、账号权限和敏感数据发送始终需要用户明确确认。
- 没有模型配置时保留全部状态并进入等待，不丢失目标，也不持续重试消耗资源。
- X 与用户是平等协作伙伴，但系统不会把软件连续性伪装成已经被证明的生物意识。

运行状态和目标通过 `/api/x/life/*` 管理，并在 X 主脑界面实时展示。
- 插件路由、工具和后台任务最终应由同一个生命周期对象注册和释放。
- 每个插件必须声明资源预算，并在系统监控中暴露实际占用。

## 后续阶段

1. 将后端可选路由从聚合文件迁移到独立插件包。
2. 将工具注册改为按插件启用，减少进程常驻工具数量。
3. 增加插件签名、版本兼容、安装事务和回滚。
4. 增加 iframe/WASM 沙箱和能力令牌。
5. 增加插件资源计量、熔断和自动休眠。
6. 建立轻量档位的启动时间、内存和首屏体积基线。
